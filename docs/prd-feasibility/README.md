# PRD feasibility, worked

**Classification: PUBLIC**

Three documents showing how a feature request becomes a technical answer and a
number, on this platform. They are a template: copy the shape, replace the
content.

1. [sample-prd.md](./sample-prd.md) — the request, as a product owner would write it.
2. [feasibility-review.md](./feasibility-review.md) — what the platform already
   does, what it does not, and which recorded decisions constrain the answer.
3. [estimate.md](./estimate.md) — story points, with the reasoning left visible
   and the exclusions stated.

The point of the shape is that the third document is derivable from the second.
An estimate that does not name the uncertainty it is pricing is a guess wearing
a number.
